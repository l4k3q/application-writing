# 申请文书写作

结合申请人的真实经历与目标机构的实际要求，依次完成信息搜集、brainstorm、结构分析、风格选择、起草与修订。信息搜集后在本次申请材料目录落地 `requirements.md` 和 `doc/` 样例记录，brainstorm 后落地 `portrait.md`；文件规则见[申请记录](references/application-records.md)与[样例调研](references/example-research.md)。允许通过选材、定位、解释经历意义和调整表达来增强说服力；不要把“包装”误作虚构事实。用户只要求其中一阶段时，完成该阶段即可；沿用已有材料，不要求重复提交。

## 1. 搜集和核对信息

- 先识别文书类型、申请项目、申请年度、截止日期、目标语言、题目、字数或页数、格式和提交方式。PS 与 SOP 的名称在不同机构可能互换，以该机构的具体题目为准。
- 需要查目标机构时，优先阅读官方招生页面、项目页面、申请系统说明和院系或导师的一手资料，记录链接和查看日期。主动寻找与申请人经历可能相接的研究问题、课程或培养方式；区分硬性要求、项目特色与个人适配推断。时效性信息在写作前重新核对；只有项目名称而没有要求时，不臆测题目或限制。
- 搜索目标学校及相近项目的官方 PS/SOP 写作指南和公开的优秀或带批注样例。可用 `SOP example + 学校名 + 专业`、`personal statement example + 学校名` 等检索式；优先学校招生办公室、写作中心与院系页面。按[样例调研](references/example-research.md)为每篇相关样例在本次申请材料目录的 `doc/` 下建立一个 Markdown 文件，附原文链接、来源性质、写法分析及适用边界。不能把样例当成目标项目的硬性要求。
- 汇集申请人提供的 CV、成绩、经历、作品、研究、目标和旧稿。原始材料是线索，不是成稿结构；可据此提出尚未写明的关联供申请人判断。对重要表述保留来源、时间、个人贡献和确认状态；不同材料互相矛盾时列出冲突，不挑有利版本。已有账本将某主张标为“不采用”时，除非获得新的可靠证据并重新确认，否则不写入草稿。
- 只有申请人能提供的动机、亲历、心理、推荐人观察或未公开成果，不从公开资料推造。公开资料可以丰富目标机构与领域背景，不能替申请人证明个人感受。缺少会改变主线的材料时，在 brainstorm 中集中询问最关键的问题。
- 不把真实个人信息写入本 skill 的示例、模板或公开文件；只按当前用户要求放入其文书。
- 完成该阶段后创建或更新本次申请的 `requirements.md`：列出文书题目、硬性限制、资格与提交要求，并为每项给出可回查的官方来源、核对日期和适用申请周期。建议与未核实信息分开列示，不能充作强制限制。已有文件先阅读并保留用户已确认的修正。

## 2. 写前 brainstorm

- 新写或大幅重写前，先读[选题与联系分析](references/brainstorm.md)。根据目标项目、已有经历和公开信息，提出 2–3 条不同的候选主线，而非直接把中文履历译成英文。每条展示核心判断、可用事实、经历之间的联系、与目标项目的联系，以及尚需申请人确认的地方；比较证据强度、项目契合与独特性，明确推荐一条并解释理由。
- 用少量具体问题启发申请人回忆选择、困难、取舍、变化和下一步想验证的问题。将“材料已证明的事实”“基于事实的解释”和“待确认的个人判断”分开；允许申请人否定或组合候选角度。
- 若申请人不清楚好文书的标准、主线或未来方向，先结合本次题目、官方指导和与其材料相近的样例解释判断依据，再主动提出暂定方向；不要把“选哪个”“职业目标是什么”原样交还用户。事实足够时据推荐方向继续规划和起草，让用户针对具体内容修正；仅当亲历、动机或贡献的缺口会影响真实性时集中追问。用户明确要求直接出稿，或已有明确主线时，可内部完成 brainstorm，并在草稿旁简短说明采用的角度与待确认判断；小幅润色无需重复完整 brainstorm。
- 完成该阶段后创建或更新本次申请的 `portrait.md`：记录从申请人材料、可核验证据和本轮回答中得到的客观信息及来源、日期、确认状态、个人贡献边界。候选叙事角度、推测的动机和文风判断不写成客观事实；材料冲突或缺失单列待核对。已有文件先阅读并保留用户已确认的修正。

## 3. 分析文书结构

- 先把题目和评审关注点拆成需要回答的问题，再将申请人的证据与之对应。区分已有事实、可合理解释的判断、待确认信息和真实缺口。
- 从选定的主线推出段落功能，写清每段的判断、证据，以及它如何引出下一段；检查是否重复 CV、是否回答题目、是否符合字数。结构由材料和题目决定；需要结构启发时可按文书类型查阅 `assets/` 中的原创模板，但不照填模板或替代本次申请的真实材料。
- 只读取当前文书对应的参考文件：[PS](references/ps.md)、[RL](references/rl.md)、[CV](references/cv.md)、[SOP](references/sop.md)、[暑研申请信](references/research-cover-letter.md)。多文书任务读取涉及的文件，并核对日期、职位、项目、成果和目标的一致性。

## 4. 选择语言风格

- 根据目标语言、学科、受众、文书类型和用户已有文字，给出简短的风格判断；用户指定语气时以用户要求为准。保留申请人的表达习惯，不制造口头禅、戏剧化细节或夸张的“个人故事”。
- 对美国申请文书，优先让具体选择、行动、结果与反思支撑能力、passion 和 goal 的陈述，即“show, then tell what it means”；仍需清楚说出目标与项目契合。PS 的个人叙事通常可以更强，SOP 更直接地说明学术或专业问题、准备和下一步。以具体项目的题目和查到的官方指导调整。
- 让具体行动、选择、限制和反思承载个人声音。每段应增加新事实、新判断或新的关联；抽象赞美、重复总结和没有材料支撑的细节不能用来凑字数。完整检查见[语言与修订](references/style-and-revision.md)。
- 不机械套用其他写作 skill 对中文标点、句式或材料数量的硬规则；以申请题目、语言和真实材料为准。

## 5. 起草与修订

- 按已选结构起草，围绕申请人的判断和项目契合重新组织素材，不逐句翻译原材料。所有头衔、日期、成绩、排名、数字、论文状态、项目参与程度和机构信息须有依据；团队成果与个人贡献分开写。未经确认的强主张只留在带标记的内部草稿，不进入可直接提交的版本。
- 起草时读取本次申请的 `requirements.md`、`portrait.md` 和相关 `doc/` 样例分析，并回查关键来源。前两份记录是约束与事实基线，样例是写法参考；均不是逐句改写的模板。文件内的待核对项不自动变为成稿事实，不复用样例作者的个人经历或独特措辞。
- 起草时同时设计文书版式，不只输出连续正文。先遵守项目规定的文件格式、页数和题目；未规定时按文书类型使用清晰的标题或信息栏、段落留白、栏目及落款，不为装饰而增加无关元素。具体版式见对应文书参考文件。
- 交付每份文书的审阅稿时，先放完整的目标语言版本，紧接着以明显分隔和“中文参考译文”标题放完整中文版本；译文与正文的段落、栏目或条目对应，不增加、遗漏或强化事实，姓名、机构、项目与术语保持准确。中文只供核对。若需生成上传文件或可直接提交的版本，另提供只含申请要求语言的版本，并按 `requirements.md` 核对字数、页数和文件格式；不得把译文混入提交版。
- 修改现有稿时先保留有效的具体内容，解决题目覆盖、结构和事实问题，再处理语言。解释关键修改理由，避免只给一篇无法对照的新稿。
- 交付前核对机构要求、事实、跨文书一致性、字数或页数和语言质量。明确列出仍需申请人或推荐人确认的事项；不把研究笔记和待确认占位符混进定稿。
- 不代替推荐人作证，也不把申请人自述伪装成推荐人亲眼观察。RL 的身份与审核边界见[推荐信](references/rl.md)。
