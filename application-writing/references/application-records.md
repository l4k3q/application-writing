# 申请记录：requirements.md 与 portrait.md

两份文件是每次申请的工作产物，放在用户指定或现有的该申请材料目录中，不放进 skill 目录；公开样例的分析文件另放该目录的 `doc/`，格式见[样例调研](example-research.md)。多所机构分别保存 `requirements.md`；`portrait.md` 可复用已核实的个人事实，但每次申请都要标明与当前目标相关的经历和最新状态。若同名文件已有内容，先读取、核对并更新，不无故覆盖用户修正。

## 信息搜集后的 requirements.md

文件开头写目标机构、项目、申请周期、目标文书和最近核对日期。逐项记录真正约束申请的要求，至少检查是否存在：

- 资格条件与申请时间，包括截止时区；
- 必交文书、题目原文或准确链接、语言、字数或页数、文件格式；
- 推荐信数量及提交方式、作品或附加材料要求；
- 对申请人代写、AI 辅助或材料真实性的明确规定（若机构公布）。

每项限制写明：**要求内容、适用文书或申请环节、官方来源标题与 URL（或申请系统页面位置）、核对日期、适用年度**。需要时附简短原文片段以便回查，不大量复制页面。只有往年页面、非官方整理或截图时，标为“待官方确认”；未找到的信息写“未查到”，不要推断为“无限制”。单列项目特色或写作建议，避免与硬性要求混淆。来源相互冲突时保留双方及冲突，不自行挑选。

## brainstorm 后的 portrait.md

文件开头写申请人标识、本次申请目标、材料范围和最近核对日期。按实际材料记录教育、时间线、课程与成绩、研究或项目、个人职责、成果与状态、技能、奖项、目标约束等客观信息；没有证据的栏目无需补齐。

对重要事实保留：**事实内容、来源文件或用户明确陈述的位置、时间或口径、确认状态、个人贡献边界**。用户自述可以标为“用户自述”，不能伪称已由第三方核验；公开作品或成绩单可注明可核对位置。冲突、不采用、过期和待补信息另列，禁止悄悄合并为更强的版本。

brainstorm 得到的候选主线、假设性解释、个人感受和机构匹配判断不属于客观画像。只有申请人确认了其中的实际选择、行动或结果，且记录来源后，才将这部分事实加入 `portrait.md`；主观动机仍在文书规划中表达并请申请人确认。

## 后续使用

结构规划与起草同时读取两份记录：`requirements.md` 限定可提交形式，`portrait.md` 限定可使用的个人事实。页面规则可能变化，提交前回查时效性要求；申请人信息也可能更新，发现新证据时先更新记录，再修改文书。不要在公开 skill 示例或仓库中保存真实申请人的私人画像。
